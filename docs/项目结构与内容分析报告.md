## App 包内部结构（`cos/` 目录）

### 关键入口与配置

- **`cos/hooks.py`**
  - **桌面资源注入**：`app_include_css`、`app_include_js`
  - **指定 DocType 的 JS 注入**：`doctype_js`（如 `Item`、`Item Group`、`Company`、发票税务登记相关脚本等）
  - **DocType 事件钩子**：`doc_events`
    - `New Item Request.before_save`：计算参数指纹（见 `cos/cos_stock/utils/new_item_request.py`）
    - `Item.before_insert`：自动设置物料编码（见 `cos/cos_stock/utils/item.py`）
    - `Project.before_insert`：自动设置项目编码（见 `cos/cos_stock/utils/project.py`）
    - `Address.before_save/validate`：更新地址显示（见 `cos/cos_share/utils/address.py`）
    - `Purchase Invoice/Sales Invoice.before_cancel/on_trash`：税务登记引用联动处理（见 `cos/cos_accounts/utils/tax_registry_reference.py`）
  - **方法覆写**：`override_whitelisted_methods`
    - 覆写 `frappe.desk.search.search_link` → `cos.cos_share.controllers.search.custom_search_link`
  - **登录/会话钩子**：`on_login` / `on_session_creation`
    - 指向 `cos.cos_logto.controllers.oauth2_handler.on_login`
  - **fixtures 策略**：对 Report/Client Script/Server Script/Custom Field/Property Setter/Print Format 等进行导出过滤（对应 `cos/fixtures/*.json`）

- **`cos/modules.txt`**：决定“模块”在 Desk 中的归类/显示

- **`cos/patches.txt`**：数据库迁移补丁入口
  - `pre_model_sync`：`cos.patches.v1_2.rename_uom_cn`

### 子模块（按业务域划分）

#### `cos/cos_share/`（通用能力/共享）

- **控制器**
  - `controllers/search.py`：自定义 Link 搜索
    - 兼容 Frappe 升级：通过 `inspect.signature()` 过滤/保留合法参数
    - 搜索串预处理：把 `5*100`、`5x100` 等规格写法归一为 `5%100` 以提升匹配
- **DocType**
  - `executive_standard` / `external_link` / `source_type`
- **utils**
  - `utils/address.py`：地址显示字段同步/修正
- **workspace**
  - `workspace/cos/cos.json`：COS 工作区配置

#### `cos/cos_stock/`（物料/库存相关扩展）

- **DocType**
  - `New Item Request`：新物料申请/建码入口（可提交）
  - `Item Parameter Template` +（子表）`Item Parameter Template Definition`：参数模板与模板明细
  -（子表）`Item Parameter Definition`：申请单参数明细
  - `Item Base Name` / `Item Color` / `Item Material` / `Item Surface`：物料维度/属性字典
- **utils**
  - `utils/new_item_request.py`：参数指纹计算（MD5）
    - 从 `parameters` 子表中挑选 `join_to_hash=1` 且 `constraint_type != "Format"` 的行
    - 标准化后拼接为 `key=value|...` 并生成 `unique_code`
  - `utils/item.py`、`utils/project.py`：自动编码等业务规则（由 `hooks.py` 触发）
- **controllers**
  - `controllers/new_item_request.py`：与申请单相关的服务端逻辑（入口位置）

#### `cos/cos_accounts/`（财税/公司信息相关扩展）

- **DocType**
  - `Tax Registry`：税务登记（可提交）
  -（子表）`Tax Registry Item`：登记明细（动态链接到发票）
- **controllers**
  - `controllers/company.py`、`company_tax.py`、`tax.py`：公司/税务相关控制器（入口位置）
- **utils**
  - `utils/tax_registry_reference.py`：发票取消/删除时处理税务登记引用
    - 取消前：设置 `ignore_linked_doctypes += ["Tax Registry"]` 且 `doc.flags.ignore_links=True`
    - 清空发票字段 `custom_tax_registry_reference`（不强制联动修改 Tax Registry）

#### `cos/cos_logto/`（Logto 社交登录集成）

- **DocType**
  - `Logto User Settings`：Logto 用户设置（Single）
- **controllers**
  - `controllers/oauth2_handler.py`
    - 在 `on_login` / `on_session_creation` 场景中，若用户通过 provider `COS` 登录（或存在 `User Social Login` 记录），自动绑定角色 `Logto User`

## 风险点与建议（面向维护）

- **Python 版本约束**：`pyproject.toml` 标记 `requires-python = ">=3.14"`，而常见 Frappe/bench 环境未必使用 3.14；建议确认这是否为“目标约束”还是“误填/过严”，以免安装/打包流程受阻。
- **强耦合扩展点**：`override_whitelisted_methods` 覆写 `search_link` 影响范围较大；当前实现已通过签名过滤提高兼容性，建议在升级 Frappe 时重点回归该路径。
- **税务登记引用处理**：`tax_registry_reference.py` 选择“清空引用字段 + 忽略链接校验”为主，避免系统流程被拦截；若未来业务要求在取消/删除时同步修改 Tax Registry，需要补充明确的联动策略与权限边界。
